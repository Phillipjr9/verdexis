COMMON MISTAKES TO AVOID:
=======================

1. ❌ Using original password instead of URL-encoded
   Wrong: S5C<K#5-K)|J8_K:O:o)GZ<mIkI*
   Right: S5C%3CK%235-K%29%7CJ8_K%3AO%3Ao%29GZ%3CmIkI%2A

2. ❌ Missing ?sslmode=require
   Wrong: postgresql://user:pass@host:5432/postgres
   Right: postgresql://user:pass@host:5432/postgres?sslmode=require

3. ❌ Missing ?schema=public
   Wrong: postgresql://user:pass@host:5432/postgres?sslmode=require
   Right: postgresql://user:pass@host:5432/postgres?schema=public&sslmode=require

4. ❌ Wrong host
   Wrong: localhost or 127.0.0.1
   Right: database-2-instance-1.c0xwa6wyga3m.us-east-1.rds.amazonaws.com

5. ❌ Missing @
   Wrong: postgresqlusernamepassword@host
   Right: postgresql://username:password@host

6. ❌ Wrong separator
   Wrong: postgresql://username password@host
   Right: postgresql://username:password@host

ENVIRONMENT VARIABLE FORMAT:
===========================

Render accepts:
DATABASE_URL=postgresql://...

Do NOT use:
export DATABASE_URL=postgresql://...
set DATABASE_URL=postgresql://...
"DATABASE_URL" = postgresql://...

Just enter the value exactly as shown above.

===========================

WHAT db.ts DOES WITH THE URL:
============================

1. Reads DATABASE_URL from environment
2. Checks for special characters (%XX encoding)
3. Detects if it's an RDS connection (contains rds.amazonaws.com)
4. Automatically adds ?sslmode=require if using RDS
5. Passes to Prisma for connection pooling
6. Attempts connection with retries (5 attempts, exponential backoff)

===========================

PRISMA MIGRATION:
================

When Render deploys:

1. npm run build
   → Generates Prisma client
   → Compiles TypeScript

2. npm run start:migrate
   → Runs: npx prisma migrate deploy
   → Applies pending migrations to database
   → Then starts: node dist/index.js

This ensures database schema is always in sync with code.
