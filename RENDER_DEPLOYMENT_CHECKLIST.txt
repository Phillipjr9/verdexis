TROUBLESHOOTING
===============

Database Connection Failed:

1. Check Render Logs for error message
   - "SSL connection refused" → RDS not publicly accessible
   - "Authentication failed" → Wrong credentials
   - "Connection timeout" → Security group not configured
   - "SSL: CERTIFICATE_VERIFY_FAILED" → SSL mode issue

2. Verify DATABASE_URL in Render Environment
   Dashboard → Environment
   Check DATABASE_URL value is complete and URL-encoded

3. Test RDS Connection Manually
   From your local machine:
   psql "postgresql://postgres:password@host:5432/postgres?sslmode=require"

4. Check RDS Availability
   AWS Console → RDS → Databases
   Status should show "available"

5. Common Issues:
   - Password contains special chars? → URL-encode them
   - Database name typo? → Use "postgres" for default
   - Schema missing? → Add ?schema=public to URL
   - Port wrong? → RDS uses 5432 by default

Build Failed:

1. Check build log for TypeScript errors
2. Ensure all dependencies in package.json
3. Check Node version (must be >=20)
4. Try clearing Render build cache:
   Render Dashboard → Settings → Clear Build Cache

Service Not Starting:

1. Check "npm run start:migrate" output
2. Look for Prisma migration errors
3. Verify migrations directory exists
4. Try running locally first

Port Issues:

1. Render assigns PORT automatically
2. Environment variable PORT=4000 is used
3. Service should listen on 0.0.0.0:4000
4. Check startCommand includes npm run start:migrate

AUTO-DEPLOYMENT
===============

After initial setup, deployment happens automatically:

1. Push to main branch (or configured branch)
2. Render detects new commit
3. Trigger webhook
4. Build starts
5. Tests run (if configured)
6. Deploy to production
7. Automatic restart with new code

Disable auto-deploy in Render Settings if needed

ROLLBACK PROCEDURE
=================

If deployment fails:

1. Render auto-rollback available
   Dashboard → Deployments → Previous version
2. Click "Deploy" on previous working version
3. Service restarts with old code
4. Fix issue and redeploy
